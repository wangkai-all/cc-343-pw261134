# 字段级许可收回 · 采集管控系统（Pointwise Delivery）

供应方可以随时收回**单个字段**的采集许可，收回通知可能与正在下载的旧响应交错到达。
本系统把**许可服务、采集执行器、原始包缓存、入库消费者**四个组件接通，提供一个可操作
网页：追踪任一字段出现在哪些**包、任务和结果**里；并保证「已封存的审计证据」与
「仍可分发的数据」分开处理——清缓存不会删掉审计，旧字段也不会继续发布。

零第三方依赖，仅使用 Python 3.11 标准库 + 原生 HTML/JS；所有网络交互都是真实的本地 HTTP。

## 快速开始

```bash
./run.sh                 # 启动供应商(:8091)、Web(:8090)、worker(:8092 控制口)
# 浏览器打开 http://127.0.0.1:8090
./stop.sh                # 停止全部进程

python3 -I tests/test_e2e.py   # 28 项端到端断言（自动使用独立端口与临时目录）
```

端口、延迟、目录、心跳阈值全部可经环境变量覆盖，见 `app/config.py`。

## 架构

```
                         真实 HTTP（localhost）
 ┌────────────┐  轮询 outbox   ┌─────────────────── web 进程 ───────────────────┐
 │  supplier  │ ◀────────────▶ │ license service（许可台账 + 通知幂等 + 下架编排）│
 │ 本地真实来源│  GET /packages │ api.py（REST + 静态页面 + worker 进程监管）      │
 │ 可收回/重发 │ ◀────────────▶ └───────────▲───────────────────▲───────────────┘
 └────────────┘               下载          │ SQLite (WAL)       │ 控制口 suspend/resume
                                             │ 共享状态            │
                                  ┌──────────┴─────────┐  心跳   │
                                  │ worker（独立 OS 进程）◀───────┘
                                  │  executor 循环：租约→下载→raw_cache
                                  │  consumer 循环：入库边界逐字段过滤
                                  └──────────┬─────────┘
                              runtime/data/  ┴
                                ├─ raw_cache/   可分发原始包（可清理）
                                └─ sealed/      封存审计证据（append-only，无删除接口）
```

| 组件 | 代码 | 职责 |
|---|---|---|
| 许可服务 | `app/license.py` | 轮询通知、`notification_id` 幂等去重、维护许可台账、收回后取消/下架编排 |
| 采集执行器 | `app/worker.py` executor 循环 | 租约 QUEUED 任务，真实 HTTP 下载，写入原始包缓存 |
| 原始包缓存 | `runtime/data/raw_cache/` + `packages` 表 | 可分发数据，支持清理；活动任务占用时跳过 |
| 入库消费者 | `app/worker.py` consumer 循环 + `app/lifecycle.py` | 入库边界逐字段复核当前许可，过滤/发布，必要时封存证据 |
| 审计 | `app/audit.py` + `runtime/data/sealed/` | 哈希链 append-only 日志 + 封存包，独立校验，应用无法删除 |
| 网页 | `web/`、`app/api.py` | 10 个面板 + 4 个一键竞态场景，2 秒自动刷新 |

## 关键决策：为什么是「接收后过滤」而不是「任务取消」

**取消只能优化带宽，不能保证正确性。** 收回通知到达的瞬间，任务可能正在下载、
甚至刚下载完还没入库，任何取消信号都追不上已经在途的响应。因此：

1. **正确性锚点是入库边界（`lifecycle.ingest_package`）**：消费者在入库那一刻重新读取
   许可台账（含 `effective_time`），逐字段判定。即使下载全程许可有效、入库前 1ms 才收回，
   该字段也只会以 `filtered` 落库，永远不会进入可分发结果。
2. **取消仅作用于 QUEUED 任务，且只取消请求字段全部被收回的任务**
   （`cancel_fully_revoked_queued_tasks`）。只要还有一个字段有效，任务就保留，
   由消费者剥离失效字段、发布其余字段。
3. **在途下载不硬杀**：让它走完 HTTP 再由消费者过滤，避免半截响应与状态机复杂度；
   原始包同时被封存为证据。
4. **已发布结果的收回（takedown）**：`take_down_published_field` 先封存原始包，
   再把结果置为 `withdrawn` 并删除可分发值（`results.value = NULL`），行、哈希与血缘保留。

## 四个难题的处理方式

### 1. 通知重发
供应商 outbox 重发时分配**新 `seq` 但保持 `notification_id` 不变**。许可服务按
`notification_id` 去重：重复通知只更新投递位点，不重复改台账、不重复下架。
测试 3 与网页「重发通知」按钮可核对（审计中 `license.revoked` 只有一条）。

### 2. 工作进程离线
worker 是真实子进程，停止即心跳过期（超过 `WORKER_OFFLINE_AFTER` 秒判定离线）。
离线期间许可服务照常摄入通知、任务留在 QUEUED；worker 重启时执行 `catch_up()`
重放全部已知通知（幂等），再处理积压任务，离线期间的收回照样生效。

### 3. 下载刚完成就收回许可
消费者在入库时才做许可判定，所以「下载窗口内收回」与「下载完成后、入库前收回」
由同一段代码覆盖。网页场景 A 与测试 2 专门构造这个竞态（供应商有可调下载延迟
`SUPPLIER_LATENCY_SECONDS`），断言失效字段零发布且原始包被封存。

### 4. 审计证据与可分发数据分离
- 物理隔离：`raw_cache/`（可清理）与 `sealed/`（只追加）是两个目录；
- `evict_cache()` 只解析 `raw_cache/` 内路径，越界路径直接跳过，代码里根本没有
  删除 sealed 的能力；活动任务占用的缓存也会跳过；
- 审计日志是哈希链（每条记录包含前一条的 hash），删除/篡改任一行都会被
  `/api/audit/verify` 检出（测试 7 实测）。

## 网页能做什么

1. worker 启动/停止（真离线）/挂起/恢复，心跳与在线状态
2. 许可台账：每字段许可状态、生效时间、来源通知、结果计数；一键收回/恢复
3. 通知面板：seq 与稳定 id、处理时间、单条重发、手动拉取
4. 任务面板：创建采集任务（包 × 字段）、状态机、QUEUED 任务手动取消
5. 四个一键场景：A 在途竞态 / B 重发去重 / C 离线收回 / D 取消 vs 过滤边界
6. 字段血缘：一个字段出现在哪些包（值哈希、缓存/封存位置）、任务、结果、通知历史
7. 缓存与封存双面板：清理缓存、封存证据列表、哈希链校验
8. 哈希链审计日志（全量动作与载荷）
9. 供应商真实请求日志（每次下载/轮询/收回都可交叉核对）
10. 应用日志

## 本地来源如何核对

- 供应商是独立 HTTP 进程，`/admin/requests` 记录它服务过的**每一个真实请求**
  （网页第 9 面板）；
- 下载的原始字节保存在 `runtime/data/raw_cache/*.json`，封存副本在
  `runtime/data/sealed/*.sealed.json`，可直接 `sha256sum` 与库中哈希比对；
- 所有状态在 `runtime/state.sqlite3`，所有动作在 `audit_log` 哈希链；
- 「重置环境」会停 worker、清空 runtime、复位供应商，回到可复现的种子状态。

## 目录

```

  config.py     全部可调参数（env 覆盖）
  db.py         SQLite schema 与连接管理（WAL，多进程安全）
  supplier.py   可控本地来源 + 通知 outbox（重发/轮询）
  license.py    许可服务：幂等摄入、轮询线程、catch-up

tests/          端到端测试（28 项断言）
```
